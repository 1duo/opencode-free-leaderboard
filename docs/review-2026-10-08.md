Controlled checks showed that changing the working directory or using the built-in agent did not fix the rejection; retaining native file/shell schemas did. No client headers, model IDs, or provider identities were spoofed.

Each tool and access to external directories requires permission, and the runner rejects every permission request. All other tools, including delegation and network tools, are denied. Continuation after denial is explicitly disabled. Live diagnostics forced a shell request and an external-file write. Each confirmed one rejected permission, no execution, one assistant turn, and no repair turn. Revision 4 exposed a distinction in the client: automatic filesystem denial can trigger another turn, while a rejected permission stops continuation. Revision 5 routes external-directory access through rejected permission as well. All revision 4 answers are archived and excluded; the corrected configuration receives fresh answers.

Every question still uses a fresh session, the fixed benchmark agent, original benchmark system/user roles, and the pinned OpenCode 1.18.31 client. Environment context and native schemas are disclosed. Plugins, auxiliary agents, parallel tasks, sharing, and compaction are disabled. Only freshly verified, exact zero-price Zen IDs are selectable. Each configuration has a distinct evaluation epoch. Earlier API and native configurations remain private and are excluded from current results; no benchmark answers are reused.
